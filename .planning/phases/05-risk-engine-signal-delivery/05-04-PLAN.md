    **src/poseidon/risk/pipeline.py** — `class SignalPipeline`:
    - `__init__(self, db_session, redis_url: str | None = None)`:
      1. Store `self._db = db_session`
      2. Create `self._engine = RiskEngine()`
      3. Create `self._portfolio = VirtualPortfolio()`
      4. Create `self._delivery = SignalDeliveryService(redis_url or settings.redis_url)`
      5. Create `self._repository = SignalRepository(db_session)`
      6. Call `self._portfolio.rebuild_from_db(db_session)` to restore portfolio state from signal history

    - `process(self, signal: Signal) -> Signal`:
      The main entry point. Strategies call this with their raw signals.
      1. Load rules from DB for this evaluation cycle: `self._engine.load_rules_from_db(self._db)` — this ensures RISK-03 hot-reload works
      2. Run risk evaluation: `signal = self._engine.evaluate(signal, self._portfolio)`
      3. Persist signal to DB (both passed AND rejected): `self._repository.save(signal)`
      4. If `signal.status == SignalStatus.PASSED`:
         a. Update portfolio: `self._portfolio.apply_signal(signal)`
         b. Deliver to Redis: `self._delivery.deliver(signal)`
      5. Commit DB transaction: `self._db.commit()`
      6. Return the signal (with status set)

    - `process_batch(self, signals: list[Signal]) -> list[Signal]`:
      Process multiple signals. Call `self.process(signal)` for each. Return list of processed signals.

    Import from: `poseidon.risk.engine`, `poseidon.risk.portfolio`, `poseidon.signals.delivery`, `poseidon.signals.repository`, `poseidon.signals.schemas`, `poseidon.core.config`.

    - `RiskRuleCreate(PydanticBase)`: rule_type (str), name (str), enabled (bool = True), priority (int = 0), params (dict = {})

    - `RiskRuleResponse(PydanticBase)`: id (UUID), rule_type, name, enabled, priority, params, created_at, updated_at. Set `model_config = {"from_attributes": True}`

    4. `PATCH /api/risk-rules/{rule_id}` — Update rule fields (enabled, priority, params). Only update fields that are not None. Commit, return updated `RiskRuleResponse`.
    5. `DELETE /api/risk-rules/{rule_id}` — Delete rule. Raise 404 if not found. Return 204.
    6. `GET /api/risk-rules/types` — List available rule types from RULE_REGISTRY. Return `list[str]` (keys of RULE_REGISTRY).
